# AI Tavern Lite 稳定性与安全修复设计

## 目标

在不重写现有产品的前提下，修复已确认的聊天数据一致性、停止生成、重新生成、设置持久化、数据库路径和发布包泄密问题，并让测试覆盖真实接口行为。

## 范围

### 聊天链路

- 当前用户消息只进入模型 Prompt 一次。
- SSE 在生成第一段内容前发送包含用户消息与助手占位消息的 `message` 事件，前端以服务端 ID 为准。
- SSE 结束时发送带最终状态的 `done` 事件；错误发送脱敏后的 `error` 事件。
- 停止请求使 provider 中止，流生成器最终保留 `stopped`，不得覆盖成 `complete`。
- 重新生成必须走 `/chat/regenerate`，删除数据库中的上一条助手回复后再生成。
- 新消息和生成状态变化必须更新会话 `updated_at`。

### 设置

- 数据库值默认生效；仅显式设置的环境变量覆盖数据库。
- `clear_api_key` 在普通键过滤前处理。
- 设置页提供清除密钥操作。
- 数值参数增加边界验证，`max_tokens` 必须小于 `context_window`。

### 数据与发布

- SQLite 默认路径基于后端目录解析，不依赖启动工作目录。
- Memory 的 `session_id` 建立外键和关系级联。
- Message 增加 `(session_id, sequence)` 唯一约束；接口自行计算序号，不信任客户端序号。
- `.gitignore` 覆盖后端数据、备份、缓存、构建产物和临时文件。
- 交付压缩包不包含数据库、API Key、备份、node_modules、缓存或构建产物。

## 兼容性策略

- 保留现有 HTTP 路径和主要 JSON 字段。
- SSE 仍使用 `data:` 帧；新增结构化 `message` 和 `done` 事件，继续兼容 `content` 与 `[DONE]`。
- 不引入新的运行时依赖。
- 对现有 SQLite 数据库不自动执行破坏性迁移；新约束用于新建数据库，关系级联同时在 API 删除路径显式处理以兼容旧库。

## 错误处理

- 后端日志与前端错误消息统一经过 API Key 脱敏。
- 前端流被用户主动 abort 时不显示网络错误；最终状态由停止接口和本地状态共同收敛为 `stopped`。
- 流式请求失败时助手占位消息保留并标记为 `error`，便于用户看到失败位置。

## 测试

- 后端：Prompt 去重、停止最终状态、重新生成数据库一致性、设置持久化/清除、会话更新时间、路径稳定性和删除记忆级联。
- 前端：通过 TypeScript 构建检查 API 事件类型和 Zustand 状态更新；移除跨平台 `node_modules` 后用干净安装验证构建。
- 最终验证：后端完整 pytest、前端 `npm ci && npm run build`、敏感文件扫描和交付包清单扫描。
