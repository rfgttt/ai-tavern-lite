# AI Tavern Lite 3～5 分钟演示脚本

## 演示前准备

- 使用专门的演示角色和会话，不展示私人聊天；
- 默认先使用 Mock 模式，真实模型只展示一条短回复；
- 清除浏览器通知和桌面隐私信息；
- 浏览器缩放保持 100%；
- 提前打开终端，但不要显示 API Key；
- 准备 `verify-release.ps1` 最后一页通过结果截图；
- 录制分辨率建议 1920×1080。

## 0:00—0:25 项目定位

画面：项目首页与角色列表。

讲解：

> 这是 AI Tavern Lite，一个本地优先的 AI 角色卡运行平台。前端使用 React、TypeScript 和 Zustand，后端使用 FastAPI、SQLAlchemy、SQLite 和 Alembic，通过 SSE 接收模型的流式回复。它不只是聊天界面，还会为每个会话维护独立的角色、Persona、世界书、剧情状态和时间线。

## 0:25—1:05 角色与开场白

操作：打开角色管理，展示基本信息、世界书和开场白标签页。

讲解：

> 项目支持 Character Card V2/V3 的 JSON 和 PNG 导入，也可以在界面中创建和编辑角色。世界书保留关键词、常驻、启用状态和概率等结构字段。开场白支持主开场和多个备用开场，并在保存前检查空值和重复内容。导出时会保留未知扩展并输出严格 CCv3 结构。

## 1:05—1:45 新会话向导

操作：创建新会话，依次展示单人/编组、主角色、Persona、标题、开场白来源和初始状态。

讲解：

> 新会话可以选择单角色或多人编组，绑定默认或指定 Persona，也可以不绑定。开场白可以使用主开场、备用开场或空白。初始状态支持 JSON 覆盖，但后端会拒绝危险路径、错误类型和超限内容。多人会话还会验证主角色确实属于所选编组。

## 1:45—2:35 流式聊天与控制

操作：使用 Mock 发送一条消息，在生成中点击停止；再展示重新生成和 Prompt 预览。

讲解：

> 聊天通过 SSE 流式返回。用户可以停止生成、重新生成最后一条回复，并查看 Prompt 各部分的预算。模型配置会在前端和后端两次校验；后端在写入待生成消息前完成校验，因此配置错误不会留下空助手消息。浏览器切换会话后，旧流的内容和错误回调也不会污染新会话。

## 2:35—3:10 运行时与回滚

操作：展开运行时状态、时间线或本轮状态变化，展示分支或回滚入口。

讲解：

> 模型正文和隐藏状态补丁是分开的。平台只接受安全的状态操作，不执行角色卡中的任意 JavaScript。每轮可以查看状态变化，重新生成、删除最新回复或剧情回滚时，相应状态也会恢复。

## 3:10—4:00 工程质量

画面：终端中的发布验证通过结果、Git log、数据库迁移状态。

讲解：

> 项目不是只验证页面能打开。目前有 161 项后端测试和 36 项前端测试，包含角色卡兼容、SSE、运行时、数据库迁移、安全和快速切换竞态。数据库由 Alembic 管理，当前版本是 20260717_0001。前端 Store 和后端聊天路由都做过模块化，发布前统一运行 TypeScript、测试、迁移图检查和生产构建。

## 4:00—4:35 一个 Bug 案例

画面：`docs/BUG_CASES.md` 或简化流程图。

讲解：

> 例如早期自动验收把 SSE 的 `[DONE]` 结束标记当作 JSON，导致接口正常但脚本报错。我先确认正文事件已经成功，再定位到协议终止帧，修复解析顺序，并加入 SSE 正常结束和异常断开测试。这个过程让我开始把 AI 输出当作待验证方案，而不是直接复制结果。

## 4:35—4:55 收尾

讲解：

> 这个项目主要证明我能够从用户体验出发发现问题，整理复现步骤，结合日志和测试验证修复，并持续维护一个前后端、数据库和模型 API 共同参与的应用。我目前重点求职软件测试、AI 产品测试和技术型产品助理岗位。

## 录制后检查

- 总时长不超过 5 分钟；
- 没有显示 API Key、数据库路径中的私人名称或真实聊天；
- 操作没有长时间等待；
- 字幕中的技术名词拼写正确；
- 视频标题包含项目名、岗位方向和技术关键词；
- 简历和仓库使用同一组测试数字。
